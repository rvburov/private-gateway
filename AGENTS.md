# Правила разработки

- Автор и коммитер всех новых коммитов: `Roman Burov <romanburov89@gmail.com>`. Не добавлять соавторов или подписи других авторов.
- Использовать Go, PostgreSQL 18, pgx/v5 и SQL-запросы sqlc. SQLite не использовать.
- Xray передаёт трафик независимо от PostgreSQL; API меняет конфигурацию только после проверки Xray и с откатом при ошибке restart.
- Сохранять различие между желаемой и применённой ревизиями. Отзыв в базе требует успешного применения к работающему шлюзу.
- Секреты держать вне Git. Профили выдавать только через отдельную авторизованную операцию, не включать их в аудит или журналы.
- В production запускать браузер отдельным Docker-контейнером с непривилегированным UID, без Docker socket, host mounts и шлюзовых секретов. noVNC и API доступны через HTTPS Caddy; внутренние порты наружу не публиковать.
- Не менять производственный VPS, firewall, SSH или службы без отдельной задачи развёртывания.
- Для разработки использовать существующий checkout. Облачная задача уже изолирована; отдельный worktree не создавать без явного запроса.
- Перед коммитом выполнять `bash scripts/dev.sh test`. Проверки PostgreSQL и настоящего Xray не считать выполненными, если они были пропущены.
- После изменения SQL запускать sqlc 1.30.0. Не править вручную файлы `internal/storage/db`.
- При установке сохранять проверку TLS, подписей пакетов и контрольных сумм артефактов.
