# Проверка маршрутизации и утечек

VPN и прокси задают разные границы маршрутизации. Системный туннель может перенаправлять трафик нескольких приложений; прокси используется только теми приложениями, которые настроены на него. Профиль VLESS + REALITY описывает соединение с Xray, но сам по себе не гарантирует маршрутизацию всего устройства. Она зависит от режима клиента, ОС, DNS и правил маршрутов.

Эти проверки выполняют на реальном клиентском устройстве после успешного применения конфигурации. Модульные тесты API и `/readyz` не подтверждают отсутствие клиентских утечек. Проверочные сайты получают ваш адрес; при необходимости используйте собственные диагностические endpoints.

## Раздел «Проверка» в панели

Откройте панель на проверяемом устройстве с включённым VPN, раздел «Проверка», и нажмите «Проверить». До нажатия панель никуда, кроме своего API, не обращается.

- **Что видят сайты** — проверка браузера, в котором открыта панель. Он спрашивает у `api.ipify.org` свои IPv4 и IPv6, у `ipinfo.io` — страну, провайдера и часовой пояс адреса, а у STUN-серверов Google и Cloudflare — адреса WebRTC. Затем сравнивает всё с IP сервера, который сообщает проверка VLESS-трафика, или с адресом из профилей. Проблемы: сайты видят не IP сервера, виден IPv6-адрес (шлюз работает только по IPv4), WebRTC раскрывает другой внешний адрес. Замечания: WebRTC показывает адрес в локальной сети, часовой пояс браузера не совпадает с поясом IP. Запросы идут без cookies и без адреса панели; Content-Security-Policy панели разрешает браузеру только эти три сервиса. Эти сервисы видят тот же адрес, что и любой сайт.
- **Сервер** — `GET /api/v1/checks` после входа администратора: PostgreSQL; применена ли последняя версия конфигурации; работает ли Xray с ней; отвечает ли сайт маскировки REALITY по TLS 1.3; подлинность и срок сертификата панели; настоящий VLESS-запрос к `https://www.cloudflare.com/cdn-cgi/trace` через Xray сервера с профилем самого старого активного устройства. Профиль не покидает API: временная конфигурация клиента Xray лежит в закрытом временном файле и удаляется после запроса, Xray ничего не журналирует. Счётчик трафика этого устройства вырастет на несколько килобайт.
- **10 сайтов для проверки** с ожидаемым результатом — для DNS, отпечатка браузера и повторной проверки независимым сервисом.

DNS из браузера не проверить: для этого нужен собственный DNS-сервер с уникальными именами. Kill switch, маршруты других приложений и поведение при смене сети раздел тоже не проверяет — их проверяют по таблице ниже.

## Проверки на устройстве

| Проверка | Действие | Что проверять |
| --- | --- | --- |
| Внешний IPv4 | Сравнить адрес до подключения и после него | После подключения ожидается исходящий адрес шлюза для приложений, включённых в туннель |
| DNS | Проверить используемые резолверы и запросы на выбранном тестовом домене | Запросы не обходят желаемый туннель/прокси через DNS провайдера клиента |
| IPv6 | Проверить внешнее IPv6-соединение | Оно идёт через предусмотренный маршрут либо блокируется клиентом, если шлюз обслуживает только IPv4 |
| WebRTC | Открыть страницу диагностики WebRTC в используемом браузере | Убедиться, что не раскрывается внешний адрес клиента в обход маршрута; учитывать локальные/mDNS-кандидаты |
| Kill switch | Во время передачи отключить сеть шлюза или остановить туннель | Приложения не продолжают выход напрямую, если выбран режим полного туннеля с блокировкой обхода |
| Split routing | Проверить приложения и исключения маршрутизации | Обход шлюза разрешён только для явно выбранных исключений |
| Отзыв устройства | Отозвать устройство, применить конфиг и переподключиться | Новое соединение больше не проходит; отдельно проверить поведение ранее открытых соединений |
| Ссылка-подписка | После «Новая ссылка» или «Отозвать» обновить подписку в приложении | Прежняя ссылка отвечает «не найдено», приложение не получает профиль |

На iPhone после подключения Hiddify по LTE `ipleak.net` показал исходящий IPv4 VPS `162.35.172.6`. В видимой части DNS-теста были публичные резолверы Google, WebRTC показал только IPv4 VPS и локальный адрес mDNS; IPv6-тест завершился тайм-аутом. Это результат одного устройства и одной сети, а не гарантия для Windows, другой сети или всех приложений. Kill switch, работа IPv6 при смене сети и поведение после отзыва устройства на клиенте ещё не проверены.

Удалённый Chromium на VPS вернул тот же IPv4 на `https://api.ipify.org/` и `2ip.io`. `api.ipify.org` специально выдаёт только адрес одной строкой; обычный сайт сервиса находится на `https://www.ipify.org/`. Для браузера дополнительно нужно проверить DNS, WebRTC и отсутствие нежелательного доступа к API управления и локальной сети. Браузерный процесс работает без root внутри Docker, но Docker Engine на VPS системный; это не заменяет проверку сетевой изоляции.

REALITY не скрывает все метаданные и не устраняет браузерный fingerprint, вход в аккаунты, cookies или наблюдение со стороны сервера. Владелец шлюза и внешние сервисы остаются участниками доверия. Не записывайте URI, ссылки-подписки, токены, UUID клиентов или содержимое пользовательского трафика в диагностические журналы. Сервер сам ссылки-подписки не журналирует: у Caddy нет журнала запросов, а из журнала ошибок убран URI.
