# Подключение совместимых клиентов

Шлюз использует **VLESS + REALITY по TCP** с потоком `xtls-rprx-vision`. Профиль не привязан к Hiddify: панель выдаёт стандартную ссылку `vless://` и QR-код с той же ссылкой. Подойдут актуальные клиенты, которые поддерживают **все три** параметра: VLESS, REALITY и Vision. Обычный SOCKS/HTTP-клиент или приложение без REALITY этот профиль не откроет.

## Импорт ссылкой

1. В панели откройте **Устройства → Профиль** нужного устройства. Если оно новое, сначала нажмите **Применить конфигурацию** и убедитесь, что применённая и новая версии совпали.
2. Оставьте формат **VLESS URI**, нажмите **Скопировать ссылку**. В клиенте выберите импорт **из буфера обмена / по URI / по ссылке** и вставьте её целиком. На другом устройстве можно показать QR и выбрать импорт через сканирование.
3. В клиенте выберите импортированный узел. Для перенаправления всего устройства включите его VPN/TUN-режим, если такой режим нужен и поддерживается; сам импорт узла не меняет маршруты остальных приложений.
4. После подключения откройте `https://api.ipify.org/` в браузере устройства. Он должен показать IPv4 шлюза `162.35.172.6`. Этот адрес выводится одной строкой — это нормальный ответ API. Для проверки DNS, IPv6 и WebRTC используйте [отдельную инструкцию](privacy-checks.md).

Названия кнопок отличаются по версии клиента; ищите «Import from clipboard», «Add from URL» или значок сканирования. Проверка реального подключения к текущему VPS пока выполнена только для Hiddify на iPhone по LTE. Для остальных приложений указана совместимость формата и ядра, а не уже подтверждённый внешний тест.

«Да» здесь означает, что формат ссылки подходит для импорта, а не то, что конкретная версия клиента уже проверена с этим VPS. Для столбца «требует проверки» не присылайте секретную ссылку: достаточно версии приложения и сообщения об ошибке. Клиенты без полного набора VLESS + REALITY + Vision не входят в поддерживаемую область проекта.

Ссылка содержит UUID доступа устройства. Не вставляйте её в публичный поиск, чат, issue, адрес браузера или сторонний сайт-конвертер. Создавайте отдельное устройство для каждого клиента, чтобы его можно было отозвать отдельно. Панель выдаёт профиль только после входа администратора; публичную подписку по URL она не создаёт, поскольку такая ссылка раскрывала бы доступ в истории запросов и журналах прокси.

## Если клиент не импортирует одиночный URI

Некоторые приложения на базе **sing-box** и **Mihomo** ожидают конфигурацию своего ядра вместо одиночной `vless://` ссылки. В том же окне профиля выберите **sing-box — JSON-файл** или **Mihomo — YAML-файл**, скачайте файл и импортируйте его в соответствующий клиент. Оба файла содержат тот же сервер, UUID, REALITY-ключ, short ID, SNI, `chrome` fingerprint и Vision flow. Они создают локальный mixed proxy только на `127.0.0.1` (sing-box: 2080; Mihomo: 7890); доступ из локальной сети выключен. Если этот порт уже занят, измените его в файле перед запуском клиента.

Оба файла прошли проверку соответствующими ядрами и локальный тест реального VLESS-трафика через Xray. Это подтверждает синтаксис и протокол, но интерфейсы импорта конкретных мобильных/настольных приложений всё равно нужно проверять на устройстве.

Скачанный файл тоже содержит секрет устройства: удалите его из «Загрузок» после импорта. Если приложение позволяет импортировать `vless://` из буфера, используйте ссылку вместо файла. Форматы не заменяют серверный протокол и не делают шлюз совместимым с клиентами без VLESS + REALITY.

Если импорт не удался, проверьте, что вставлена вся ссылка, клиент поддерживает REALITY и Vision, конфигурация Xray применена, а время устройства выставлено правильно. Для ошибки соединения проверьте серверный `vpn-smoke.py` по [инструкции развёртывания](deployment.md); открытый TCP-порт 443 сам по себе не подтверждает работу профиля. Не присылайте сюда ссылку, QR или содержимое конфигурации — достаточно названия клиента, его версии и текста ошибки без секретов.
