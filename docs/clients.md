# Подключение совместимых клиентов

Шлюз использует **VLESS + REALITY по TCP** с потоком `xtls-rprx-vision`. Профиль не привязан к Hiddify: панель выдаёт ссылку-подписку, стандартную ссылку `vless://` и QR-коды для них. Подойдут актуальные клиенты, которые поддерживают **все три** параметра: VLESS, REALITY и Vision. Обычный SOCKS/HTTP-клиент или приложение без REALITY этот профиль не откроет.

В панели откройте «Инструкции», выберите ОС и нажмите название клиента. У каждого перечисленного клиента теперь есть отдельные шаги от установки и импорта до подключения и проверки. В «Windows → Hiddify» приведены проверенные настройки системного прокси и два скачиваемых BAT-файла для программ, которые учитывают `HTTP_PROXY` и `HTTPS_PROXY`. Ссылка на загрузку клиента расположена отдельно от его инструкции. После подключения откройте на том же устройстве раздел «Проверка» ([подробнее](privacy-checks.md#раздел-проверка-в-панели)).

## Ссылка-подписка

### Переход с профиля на 443

Основной адрес панели — `https://rb-gateway-3708079.duckdns.org:8443/`. Войдите с
паролем и 2FA, откройте «Устройства → Профиль», скопируйте ссылку-подписку и
однократно импортируйте её в приложение вместо старой ссылки на недоступном 443.
Выбирать основной или резервный порт больше не требуется. Подписка, URI/QR,
sing-box, Mihomo и кнопки импорта выдают один профиль на 8443. Обновление подписки
и действие «Новая ссылка» сохраняют этот рабочий порт.

Существующие действительные ссылки `https://ДОМЕН:8443/sub/…?port=8443` продолжают
работать с тем же секретом. Прежнее `?port=primary` тоже выдаёт текущий основной
профиль на 8443, если запрос пришёл через доступный адрес. Самому параметру `port`
больше не отводится роль выбора входа. Новые ссылки не требуют этого параметра;
формат задаётся `?format=mihomo` или `?format=sing-box` (для старой ссылки с
параметром — через `&format=…`).

Приложение не сможет обновиться по подписке, чей адрес на 443 ему недоступен:
сервер не может заменить её адрес удалённо. Откройте панель на 8443 и переимпортируйте
ссылку. Старые URI на 443 сохраняют доступ там, где этот порт достижим, но наличие
двух опубликованных портов не включает автоматическое переключение клиента.

Оба входа используют одно устройство и одни ключи. «Новая ссылка» заменяет подписку
для обоих портов; «Отозвать» отключает обе подписки, а после успешного применения
конфигурации — новые VLESS-подключения на обоих портах. Проверьте доступ и внешний IP
в своей сети после переимпорта профиля на 8443. Устройства, UUID доступа и REALITY-ключи при переходе не пересоздаются.

### Обычное подключение

Основной способ подключить человека — **ссылка-подписка**: постоянный адрес `https://ДОМЕН_ПАНЕЛИ:8443/sub/…` у каждого устройства в панели. Приложение VPN само загружает по нему профиль и обновляет его раз в сутки. Ссылку можно отправить человеку, который будет подключаться.

1. В панели откройте **Устройства → Профиль**. Если устройство новое, сначала нажмите **Применить конфигурацию**.
2. Формат **Ссылка-подписка** выбран сразу. Нажмите **Скопировать ссылку** или **Показать QR-код**.
3. В приложении добавьте подписку по ссылке («Add subscription», «Add from URL», «Подписка»). Если открыть ссылку в браузере телефона, страница предложит кнопки импорта в Happ, v2rayNG, Hiddify, Streisand, V2Box и Clash Meta / Mihomo (кнопка срабатывает, если приложение установлено) и покажет ссылку для ручного добавления.

Сервер отдаёт профиль в формате приложения. По умолчанию это список ссылок `vless://` в base64 — так подписки читают v2rayN, v2rayNG, Hiddify, Streisand и Shadowrocket. Приложения Clash Meta, Mihomo и Stash получают YAML Mihomo, приложения sing-box — JSON sing-box. Формат можно указать явно: `?format=base64`, `uri`, `mihomo` или `sing-box`. JSON sing-box — настольная конфигурация с локальным proxy (см. ниже), а не VPN-профиль для телефона.

- **Новая ссылка** в окне профиля сразу отключает прежнюю: в приложениях, где она добавлена, подписку придётся заменить. Так делают, если ссылка попала не туда.
- **Отозвать** сразу отключает ссылку, а доступ — после применения конфигурации.
- Ссылка — такой же секрет, как `vless://`: кто её знает, тот подключается. В базе хранится только хеш её секрета, а сама она вычисляется из главного ключа сервера, поэтому панель может показать её снова. Сервер не пишет ссылку в журналы и аудит.

Выбор формата и страница для браузера проверены тестами сервера. На устройствах ссылка-подписка, кнопки импорта и автоматический выбор формата ещё не проверены.

## Импорт одной ссылкой `vless://`

1. В панели откройте **Устройства → Профиль** нужного устройства. Если оно новое, сначала нажмите **Применить конфигурацию** и убедитесь, что применённая и новая версии совпали.
2. Выберите формат **VLESS URI**, нажмите **Скопировать ссылку**. В клиенте выберите импорт **из буфера обмена / по URI / по ссылке** и вставьте её целиком. На другом устройстве можно показать QR и выбрать импорт через сканирование.
3. В клиенте выберите импортированный узел. Для перенаправления всего устройства включите его VPN/TUN-режим, если такой режим нужен и поддерживается; сам импорт узла не меняет маршруты остальных приложений.
4. После подключения откройте в браузере устройства панель, раздел «Проверка», и нажмите «Проверить безопасность» — или откройте `https://api.ipify.org/`: должен быть IPv4 шлюза `162.35.172.6`, одной строкой — это нормальный ответ API. Для проверки DNS, IPv6 и WebRTC используйте [отдельную инструкцию](privacy-checks.md).

Названия кнопок отличаются по версии клиента; ищите «Import from clipboard», «Add from URL» или значок сканирования. До перехода на основной 8443 реальное подключение было подтверждено для Hiddify на iPhone по LTE и для Hiddify 4.1.1 с Chrome на Windows по Wi-Fi в режиме системного прокси. После появления входа 8443 владелец отдельно подтвердил Windows + Hiddify 4.1.1 + Chrome: сайты видят IP шлюза `162.35.172.6`. Мобильная сеть с новой схемой ещё требует отдельного теста. На том же Windows-компьютере режим «VPN» показал домашний IP. Для остальных приложений указана совместимость формата и ядра, а не уже подтверждённый внешний тест.

«Да» здесь означает, что формат ссылки подходит для импорта, а не то, что конкретная версия клиента уже проверена с этим VPS. Для столбца «требует проверки» не присылайте секретную ссылку: достаточно версии приложения и сообщения об ошибке. Клиенты без полного набора VLESS + REALITY + Vision не входят в поддерживаемую область проекта.

Ссылка `vless://` содержит UUID доступа устройства, ссылка-подписка открывает к нему доступ. Не вставляйте их в публичный поиск, общий чат, issue или сторонний сайт-конвертер; `vless://` не вставляйте и в адрес браузера. Создавайте отдельное устройство для каждого человека и устройства, чтобы его можно было отозвать отдельно. Профиль и ссылку-подписку панель показывает только после входа администратора.

## Если клиент не импортирует одиночный URI

Некоторые приложения на базе **sing-box** и **Mihomo** ожидают конфигурацию своего ядра вместо одиночной `vless://` ссылки. В том же окне профиля выберите **sing-box — JSON-файл** или **Mihomo — YAML-файл**, скачайте файл и импортируйте его в соответствующий клиент. Оба файла содержат тот же сервер, UUID, REALITY-ключ, short ID, SNI, `chrome` fingerprint и Vision flow. Они создают локальный mixed proxy только на `127.0.0.1` (sing-box: 2080; Mihomo: 7890); доступ из локальной сети выключен. Если этот порт уже занят, измените его в файле перед запуском клиента.

Оба файла прошли проверку соответствующими ядрами и локальный тест реального VLESS-трафика через Xray. Это подтверждает синтаксис и протокол, но интерфейсы импорта конкретных мобильных/настольных приложений всё равно нужно проверять на устройстве.

Скачанный файл тоже содержит секрет устройства: удалите его из «Загрузок» после импорта. Если приложение позволяет импортировать `vless://` из буфера, используйте ссылку вместо файла. Форматы не заменяют серверный протокол и не делают шлюз совместимым с клиентами без VLESS + REALITY.

Если импорт не удался, проверьте, что вставлена вся ссылка, клиент поддерживает REALITY и Vision, конфигурация Xray применена, а время устройства выставлено правильно. Для ошибки соединения проверьте серверный `vpn-smoke.py` по [инструкции развёртывания](deployment.md); открытый TCP-порт сам по себе не подтверждает работу профиля. Не присылайте сюда ссылку, QR или содержимое конфигурации — достаточно названия клиента, его версии и текста ошибки без секретов.
