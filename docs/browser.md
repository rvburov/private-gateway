# Удалённый браузер

Раздел «Проверка» показывает IP, DNS, WebRTC и признаки отпечатка того браузера, в котором открыта панель. Скорость, задержки, нагрузка VPS и история замеров находятся в разделе «Сервер» и запускаются отдельно кнопкой «Проверить сервер». При запуске внутри удалённого Chromium проверки видят выход и браузер VPS, а не Wi-Fi, LTE или локальный Hiddify пользователя. Для диагностики своего подключения откройте панель в локальном браузере устройства; подробнее — в [инструкции по замерам](privacy-checks.md#скорость-и-задержка).

Основной адрес панели и noVNC использует HTTPS с обязательным `:8443`.
Если панель открыта как `https://ДОМЕН:8443/`, кнопка «Открыть» оставляет noVNC и
его WebSocket на этом же порту. Внешний 443 сохранён как совместимый вход, но
новые ссылки удалённого браузера формируются для основного адреса. Вход с паролем и 2FA обязателен; прямой запрос
`https://ДОМЕН:8443/browser/vnc.html` без cookie сеанса должен возвращать 403.
При переходе между портами может потребоваться повторный вход в панель.

Браузер запускается в отдельном Docker-контейнере с Chromium, Xvfb, VNC и noVNC. API обращается к небольшому HTTP worker внутри закрытой сети Docker; доступ к Docker socket ему не нужен. Контейнер браузера не получает ключ REALITY, мастер-ключ или доступ к PostgreSQL. Он работает под UID 10001 с read-only rootfs, без Linux capabilities, с лимитами RAM/CPU/PID и временными tmpfs для профиля и файлов. Экран VPS с одним CPU имеет размер 1280×720. noVNC передаёт изображение рабочего стола через WebSocket, поэтому его отклик зависит также от сети и браузера на устройстве пользователя.

Войдите в панель своим логином и паролем, подтвердите шестизначный код 2FA. Затем нажмите «Запустить браузер», дождитесь статуса «Запущен» и нажмите «Открыть» **в том же приложении браузера**: встроенный браузер Telegram и Safari хранят cookie раздельно. Отдельное системное окно ввода имени пользователя и пароля больше не требуется: Caddy допускает к noVNC по защищённому cookie, выданному только подтверждённому сеансу администратора. Прямая ссылка `https://ДОМЕН:8443/browser/vnc.html` без такого входа возвращает 403. Выход из панели, смена пароля и перезапуск API запрещают **новые подключения**; уже открытый WebSocket отключите кнопкой noVNC или остановите браузер до выхода. После нового входа открывайте браузер через панель. Кнопки слева внутри сеанса — меню noVNC для буфера обмена, масштаба и других настроек; это не меню сайта внутри Chromium. Порт 6080 наружу не открывается. Закрытие вкладки не завершает сеанс: нажмите «Остановить браузер», чтобы удалить временные файлы. Одновременно поддерживается один сеанс.

Адрес сайта вводите в верхнюю адресную строку **Chromium внутри noVNC**, например `https://api.ipify.org/`. Этот адрес специально возвращает только IP; на текущем VPS ожидается `162.35.172.6`. Если открылась поисковая выдача, выбран поисковый ввод или адрес распознан как поисковый запрос: выделите внутреннюю адресную строку, вставьте полный адрес с `https://` и нажмите Enter.

Серверная проверка после запуска:

```bash
sudo docker compose --env-file /etc/private-gateway-docker/stack.env \
  -f /opt/private-gateway-docker/current/docker/compose.yml \
  exec -T browser python3 /app/smoke.py --port 6080
```

Она проверяет HTTP-страницу, WebSocket, VNC handshake и размер экрана 1280×720, но не измеряет плавность работы через внешнюю сеть. При ошибке смотрите `docker compose logs browser` из [инструкции по развёртыванию](deployment.md). Старые инструкции для Podman, `pasta`, `slirp4netns` и отдельного socket worker к Docker-стеку не относятся.

На текущем VPS удалённая сессия иногда долго открывается и задерживает ввод/прокрутку примерно на 1–3 секунды даже после уменьшения экрана и качества noVNC. Во время активной прокрутки измерены CPU 1,2% без throttling и чтение диска 0 МБ за 15 секунд; ping до VPS с Windows: в среднем 163 мс, потерь 0%. Локально VNC отвечал примерно за 16 мс; замена VNC-сервера в эксперименте не ускорила его и не была развёрнута. Причина внешней задержки окончательно не установлена, поэтому повышение CPU не обосновано этими замерами. Пользователь решил оставить браузер как есть. Для обычного просмотра сайтов используйте локальный браузер через совместимый клиент VLESS + REALITY; noVNC нужен, когда важен именно сеанс на VPS. Локальные Chrome, Firefox, Safari, Brave и Tor Browser настраиваются в разделе «Инструкции → Браузеры» панели. Обычное и приватное окно проверяйте отдельно: на Windows в инкогнито Chrome уже наблюдалась WebRTC-утечка. Подробности — в [истории диагностики](troubleshooting.md).

Chromium запущен с `--no-sandbox`, поскольку его внутренний sandbox несовместим с ограничениями контейнера. Границей является Docker-контейнер, а не отдельная VM. Для более сильной изоляции браузер следует вынести в отдельную VM; это пункт [roadmap](roadmap.md). Не используйте сеанс для хранения постоянных паролей: его данные удаляются после остановки.
